# （历史）Flow 的编码节律（Cadence）设计

> **2026-10 更新：** 方案已改用键道原版四码逻辑（2 字音音全码、
> 3/4 字首字母、5 字以上前三首 + 末一首）+ 形码筛选 + 顶功，
> cadence 方案已停用。当前规则见 README「编码」「形码」两节；
> 本文保留作为设计记录。其中「形码 = 前 n-1 首键 + 末字完整形码」
> 的结论仍然有效（见第 5 节）。

本文记录 xkjd27c_flow 早期的「节奏」设计与实现路径。结论先行：

* **自动调频**只需要 Rime 内置的用户词典（`enable_user_dict`），无需 Lua。
* **节律**本质是一条码表生成规则，配合 `script_translator` 的音节图 + Poet
  整句合成即可实现，也无需 Lua。
* **Lua 留给 b 键**（形码 `aeiov`）的过滤 / 锁定 / 顶功，以及将来可能需要的
  输入预处理。

## 1. 节律定义

用 `s` 表示声母键，`y` 表示韵母键。一个「词」的完整码只允许两种形态：

```
全码：  (s y)^n              n 个字
节奏码：(s y)^(n-3) (s s s)  n ≥ 3 个字
```

即：**最后 3 个字用声母首字母，前面的字全部用全码；不允许其它位置出现
「连续声母」**。于是码长与字数的对应为：

| 键数 | 形态 | 字数 | 说明 |
|-----:|------|-----:|------|
| 2 | `sy` | 1 | 全码 |
| 4 | `sysy` | 2 | 全码 |
| 6 | `sysysy` | 3 | 全码 |
| 3 | `sss` | 3 | 节奏码（= 3 字全声母） |
| 5 | `sysss` | 4 | 前 1 字全码 + 后 3 字声母 |
| 7 | `sysysss` | 5 | 前 2 字全码 + 后 3 字声母 |
| 2n-3 | `(sy)^(n-3) sss` | n | n ≥ 3 的节奏码 |

> 注：1 键 `s` 是单字的声母码（末三字的组成单位，见第 4 节）；
> 2 键及其以上的串按奇偶拆成 `(sy)*` 和末尾的 `sss`。

## 2. 为什么 Rime 直接就能实现

码表里 code 用**空格分隔音节**（每个字的全码/声母码是一个音节）：
人工智能全码 `rk gj ;y np`、节奏码 `rk g ; n`。在 Rime 内部：

* `RawCode::FromString` 按空格切分音节，prism 音节表只有几百项；
* `Syllabifier` 在输入串上枚举所有音节覆盖；
* `Poet`（整句合成）按词频求和代价，选出最优切分。

所以只要码表同时含有下列条目：

1. 单字全码 `rk`（人）、1 键声母码 `r`；
2. 词的全码 `rk gj ;y np`（人工智能）；
3. 词的节奏码 `rk g ; n`（人工智能）；

引擎就会在「整词」「全码」「1 键尾码」之间自动取舍 —— 这就是「自适应」。
若 code 不写空格，整条长串会成为一个音节，prism 会随词数爆炸
（实测 rime-ice 88 万词：空格分音节时 prism 只有 4 KB；不分则产生
120 万个音节）。

**必须删掉 4 字及以上的「全声母」旧简码**（如 `;;;;`）。4 键在这套节律里
只能解释为 2 个全码，`;;;;` 这种码会与节律冲突。

整段节奏还由 `rime/lua/flow_filter.lua` 兜底：只要存在覆盖整段输入的
候选，就隐藏所有「前缀候选」（例如输入 `sufy` 时不会再出现 3 键的
所使用）；只有整段无法解析时才保留前缀候选。

## 3. 码表生成改动（tools/build_flow_dict.py）

**决策：词条不再自带形码，词库使用标准拼音词库；码由音码规则推导。**

形码只在运行时做筛选 / 调序，不进码表；所以词条不再需要像 CiDB 那样为
键道自定义码。只需要「词 + 拼音 + 词频」的标准数据：

* 单字：沿用 `ZiDB` 生成键道音码（全码 `sy`，另加 1 键声母码 `s`）。
* 词组：输入抽象为「标准拼音词库」；构建时把拼音映射成键道音码：
  * 默认 `pinyin_simp`（48k 词，系统自带）；
  * 可选 rime-ice `cn_dicts`：`base` 54.3 万条（词+拼音+权重）、
    `ext` 33.9 万条、`tencent` 98.1 万条（3 字以上，仅词+权重，
    靠 Rime 自动注音）、`8105`/`41448` 字表。数据不 vendored，
    用 `--words PATH` 引入（rime-ice 为 GPLv3，注意分发）。
    rime-ice 自己也不用八股文：8105 字表供音，base/ext 带词级拼音，
    tencent 无拼音，部署时由 `ScriptEncoder` 用字表自动注音。
  * 另可开 `use_preset_vocabulary: true` + `vocabulary: <name>`
    （`<name>.txt` 为 `词 + 权重`，放在用户目录或共享目录），
    让 `ScriptEncoder` 用我们的单字码自动编码全词条 —— 纯粹的
    「标准词库而不是码表」路线；代价是只用字表默认读音（多音字词汇
    会错）、只出全码、不生成节奏码。
* CiDB 不再必需；如需保留，只当额外 import 或可选源（它主要为形码服务）。

多音字：带拼音的标准词库（base / ext / pinyin_simp）本身已做了词级正音，
比让 Rime 自动注音更准，所以建议在构建时直接转换，而不是全交给
`use_preset_vocabulary`。

词频：节奏码沿用 `--abbrev-weight`（默认 0.5）。Rime 建表时权重会取
`log(weight)`，整句合成再叠加 `log(1e-6)`，因此 0.5 的 3 字简码与若干
高频单字直接拆分化合价接近，是一个需要实测调参的点。

## 4. 1 键声母码 = 节律的组成部分

节律要求「奇数长度的最后 3 键是 3 个声母」。要让这 3 个键在引擎里解析成
3 个字，最直接的做法就是**给每个单字额外生成 1 键的声母码**（`1 key -> s`）：

* 任意句子的结尾都能用 `...sss`，不要求最后 3 个字恰好是词典词；
* 整句合成会把 `(sy)^(n-3) sss` 组合出来；上屏后用户词典记住整条码，
  下次直接出整句；
* 代价：`sy` 同时有「1 个全码字」和「2 个声母字」两种解析。Poet 对每个
  条目都有 `log(1e-6)` 惩罚、条目越少越优，所以权重正常时整词 / 全码会
  自然胜出；1 键码默认权重 ×1.0（`--initial-weight`），需要时再压。

所以 5+ 字不是问题：**规则覆盖任意长度，标准词库 / 整句合成覆盖全码，
1 键码覆盖奇数结尾。**

## 5. b 键（形码）

`aeiov` 是五种笔形（㇐丨丶丿乛），不属于音码，所以不能进码表音节，
由 Lua 在运行时处理。

**形码规则（统一）**（用原版 `xkjd27c.cizu` 全量验证：38,678/38,679 吻合）：
设音码解出 n 个字，期望形码串 = **前 n-1 个字各取首键 + 最后一个字的
完整形码**；typed shape 取前缀。单字 n=1 自然就是整字完整形码，不用特判。

数据源是 `ZiDB/通常.txt` 第 3 列的前 4 笔形，构建时导出为
`xkjd27c_flow.shape.txt`（8,383 字）。笔形映射：
㇐→`v`、丨→`i`、丿→`e`、丶→`o`、乛→`a`。

例：贺礼 = 贺 `a` + 礼完整 `oaaa` = `aoaaa`（`hflyao`）；哈基米 =
哈 `o` + 基 `v` + 米完整 `oevv` = `ovoevv`（`hjmovoevv`）；不醒 =
不 `v` + 醒完整 `vioi` = `vvioi`（`bnxdvvioi`）。

输入语法：

```
输入 := 音码 (节奏码) 形码?
形码 := [aeiov]{1,8}          -- 长度 = (n-1 个首键 + 末字完整形码)
```

实现（都在用户目录的 `lua/` 下）：

* `flow_shape.lua`（`lua_processor`，speller 之前）：
  * 形码键 a/e/i/o/v 从 speller 输入里取出，存进 context property
    `flow_shape`，刷新候选（所以音码部分的节奏校验不受影响）；
  * BackSpace 先删形码；
  * **顶功**：
    * 形码后再按音码键 → 先上屏当前（形码筛过的）候选，再开始新一段；
    * 音码满 4 键后再按音码键且有候选 → 先上屏（四码自动上屏）；
      若 4 键没候选（如 5 键节奏码的前 4 键不合法），按键继续延长，
      不打断 5/7 键节奏码。
* `flow_filter.lua`（`lua_filter`）：
  * 硬性节奏校验（见第 2-4 节）；
  * 按统一规则筛选 `flow_shape`（前 n-1 首键 + 末字完整形码）；
  * 把形码接在候选 preedit 末尾显示；
  * 逐步筛选：每多一个键（音码或形码）都排除所有更短前缀当时的首选（见下）；
  * `-`/`=` 手动调序：`-` 逐级缩短（形码→声韵→1 键简码，并把完整音节
    记进 `flow_order`），`=` 逐级加长（1 键简码用记录的音节还原，
    没记录则反查；声韵以上补形码）。

例：`hjmo` = `hjm`（哈基米期望串 `ovoevv` 的前缀 `o`）→ 哈基米；
继续 `v`、`o`、`e`、`v`、`v` 逐步缩小到唯一。

**逐步筛选（自动前进）**：每多一个键（音码或形码），会排除所有更短前缀
当时的首选（同一输入下更短的形码前缀、含无形码的 base；以及更短的音码
前缀），让首选项一路前进，方便连续细选。例：`hjm`→好久没，`hjmo`→喊救命，
`hjmov`→哈基姆，`hjmovo`→哈基米；声码同样：`h`→或、`hu`→和；形码第一笔
也排除 base 首选：`fguk`→原神、`fgukv`→元神（喊救命 也满足 `ov`，这里
是主动排除；BackSpace 会恢复；全被排除时回退显示，不会空菜单）。

**候选提示**：非首选候选右侧显示「让它成为首选还需要按的键」：声码未输完时
补声码（`h`→好 `z`、会 `b`、和 `f`），声码输完后给形码（`hjmo`→哈基米
`vo`、豪杰墓 `vi`；`hjmov`→喊救命 `iv`）。键位由 reverse db 单字码按码表
拼词规则推导（`flow_codes.lua`），形码部分用自动前进模拟（`flow_filter.lua`）；
`flow_hint: false` 可关闭。

局限：整句合成出的长候选只有一个形码串（按整句字序），不能每个词各自
带形码；完整的「逐词形码 + translator」留待以后。

## 6. 实现状态（2026-10）

已实现，并用无 GUI 的 `tools/rime_probe.c`（直接调 librime）验证：

* `wum` → 为什么；`rkg;n` → 人工智能；`;gr` → 中国人；
* `uy;gr` → 是中国人（1 全码 + 3 声母合成）；
* `wumkuy;jgurk` → 我们是中国人（整句）；
* `wumku;jgurk` → 空（`u;` 非法，硬性节奏校验生效）；
* `hjmo` → 哈基米（形码按首字筛选）；`hjmo` 后再按音码键顶屏；
* `rkgj;ynp` → 人工智能（全码，并联想更长词）；
* 选词上屏后重打，候选顺序改变（用户词典调频生效）。

默认 `rime/` 用 `pinyin_simp`（6.2 万词条，table 1.9 MB）；自定义部署
已切到 rime-ice（88 万词 → 162 万词条、部署约 5 秒、table 45 MB）。
